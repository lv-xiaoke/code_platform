# CodeTop Local 完整免 Docker 桌面版设计

状态：用户已于 2026-11-18 确认设计并要求继续执行；本文件不代表功能已经实现。下一阶段为实施计划审阅。

## 目标与使用流程

用户已经选择“下载后连运行代码也完全不需要 Docker”。目标用户是不熟悉开发环境的 Windows 个人刷题用户。

对外提供一个 `CodeTop-Setup-<版本>-windows-x64.exe`。用户下载并双击安装，在常规安装向导中完成安装，之后双击桌面的“CodeTop 刷题”图标即可使用题库、笔记、代码编辑、Python 交互运行和自定义测试。无需另装 uv、Python、Node、Bun、Docker、WSL，也无需输入命令或首次下载依赖。

安装包携带应用所需依赖、前端构建、固定题库和独立 Python 运行环境。安装后基础功能及 Python 运行可离线使用；AI 助教仍需要用户自己的 Key、账户和网络。

保留现有浏览器界面：桌面入口自动启动本机服务、等待健康检查成功后打开浏览器。此次不引入 Electron、WebView 或新的桌面界面。Windows 自身的安装或发布者提示仍按系统规则处理，不以关闭系统保护作为安装步骤。

## 范围与取舍

采用“随包携带 Python + 本机子进程执行练习代码”。浏览器内 Python 会改变部分标准库及交互能力；继续使用 Docker 则无法满足本次用户选择，因此均不作为本次默认执行方式。

仅新增 Windows x64 完整桌面发行路径；保持源码开发方式和原项目根目录 `Start-CodeTop.cmd` 可用。已有 Docker 实现及其测试保留，作为维护者可显式选择的兼容运行器；桌面用户默认进入本机运行，不需要选择或了解 Docker。

本次不增加在线判题、云同步、账号、自动更新、自动安装第三方练习库或跨平台安装包。

## 本机运行的明确边界

练习代码以当前用户身份在 Windows 子进程中执行，具有该用户可用的文件与网络权限。它不是隔离沙箱。独立工作目录、Python 隔离启动参数、资源限制和进程管理都不能被描述为文件或网络隔离。

首次运行练习代码前，显示一次简短确认：“代码将在你的电脑上运行，可访问当前用户的文件和网络。请只运行你信任的代码。”确认记录仅适用于本机执行方式，不进入学习数据备份，取消时保留代码且不启动程序。之后不反复打断运行。

确认必须由服务端执行接口检查，覆盖交互运行与批量测试，不能只依赖前端按钮。接受该选择不触发管理员运行、Windows 安全设置更改或联网上传代码。

## 执行器结构

目前 `RunService` 直接创建 `DockerRunner`，`TerminalService` 直接创建 `InteractiveDockerRunner`。增加统一运行器选择模块，以显式配置选择 `native` 或 `docker`；桌面发行固定默认 `native`。不因某一种运行器失败而静默切换另一种。

本机运行器使用随发行包携带、具备标准库的独立 CPython 3.12，不从系统 PATH 查找 Python，不复制开发机 `.venv`。冻结后的服务 EXE 不能当作 Python 解释器执行用户代码；必须使用独立运行时。

现有 Linux 容器 supervisor 使用 `resource`、cgroup、`/work`、PID namespace 等机制，继续只在容器中使用。本机执行器单独实现，不移除原容器 supervisor 的检查后在 Windows 运行。

两类本机执行器共用 Windows 进程管理、编码、输出限额、工作目录与退出状态转换：

- 普通测试：每组测试启动独立 Python 进程；通过标准输入传入样例，捕获 stdout/stderr，沿用现有输出比较与结果格式。
- 交互终端：持续保持 stdin 管道，沿用当前输入、EOF、停止、增量输出和运行历史接口；支持 `input()`、`readline()`、`sys.stdin.read()` 和中文输入输出。
- 业务层继续负责请求幂等、队列、代码保存、运行历史和数据访问，不将这些规则复制进新运行器。
- 用户程序的 stdout/stderr 是纯文本流，不能作为监督进程的控制协议解析。打印类似控制消息的 JSON 不得伪造运行状态。

## 资源与进程生命周期

Windows 原生进程管理采用 Job Object，并在用户代码执行前将子进程纳入管理。不能让用户代码先运行、随后才尝试绑定资源限制。绑定失败时明确拒绝启动此次运行。

本机运行的目标限制：

| 项目 | 约束 |
| --- | --- |
| 单组普通测试 | 墙钟时间 2 秒 |
| 交互会话 | 最长 300 秒，累计计算 CPU 约 3 秒；等待输入不计 CPU |
| 内存 | 每个运行任务及其受管理子进程合计 256 MiB |
| 输入 | 每组或每会话累计 64 KiB |
| 输出 | stdout 与 stderr 合计最多 64 KiB，保留被截断前的内容 |
| 子进程 | 每个任务至多 32 个受管理进程，不允许主动脱离 Job |
| 并发 | 沿用当前普通测试队列与最多两个交互会话的上限 |

停止、超时、输出超限、关闭练习、应用退出和监督进程异常退出，都应终止其 Job 中的进程并释放句柄、管道和线程。正常主程序退出后也要结束残留子进程，防止继承的管道阻碍收尾。上述机制用于管理资源，不承诺对抗恶意代码的沙箱隔离。

工作文件按原运行编号写入该用户专用运行目录。输出持续增量读取，UTF-8 多字节字符在分块边界处不产生乱码。运行产物保留，遵守项目禁止批量删除的约束。

## 服务接口、前端与历史兼容

保留现有测试、交互终端与代码历史路由。运行器健康接口增加执行类型和展示名称，例如 `kind: native`、`label: 本机 Python`，保留现有可用性、版本与限额信息；前端不再把“可运行”硬编码显示为“Docker 已就绪”。

本机不可用时显示内置运行时缺失或启动失败等可操作信息，桌面默认模式不提示用户安装 Docker。首次运行确认文案放在运行操作附近，技术构建信息不进入普通用户安装流程。

现有学习数据及运行历史保持可读。旧记录的 Docker 镜像信息不能被改写成本机运行记录。新记录写入能明确区分本机 Python 版本的运行环境标识；兼容当前 `image_ref` 历史字段，界面按实际运行环境展示，不为字段名称给本机记录编造镜像。

## 桌面入口与发布结构

推荐使用冻结的 Windows 应用入口与后端服务，加独立 Python 运行时执行练习代码；前端、迁移文件、题库和参考程序均按明确清单附带。冻结打包须显式收录 Alembic 迁移和运行时动态导入依赖，不能仅以“EXE 能启动”认定打包完整。

安装器采用支持普通用户安装的 Windows 安装包方案（Inno Setup），程序默认安装在当前用户的应用目录，创建桌面与开始菜单入口。构建工具仅维护者需要，最终用户不需要安装这些工具。

所有 Python 运行时与构建工具固定版本和校验值，记录来源并携带相应许可声明。安装包必须携带实际依赖，不在用户首次启动时执行 pip、npm、uv 或 Docker 安装命令。安装包大小以实际构建为准，不预先承诺下载体积。

入口负责：

1. 定位安装目录、可写的数据目录及内置运行时。
2. 检查同一应用与数据目录是否已有服务，已有时复用。
3. 默认尝试本机 8000 端口；被其他应用占用时选择可用端口，不终止其他应用。
4. 设置数据目录、运行器与环境配置，启动服务，检查进程身份与健康状态。
5. 健康后自动打开浏览器；失败时显示中文错误和日志位置，不只弹出一闪而过的黑框。
6. 关闭最后一个 CodeTop 标签页后自动结束服务与本应用的练习进程；不退出用户的其他 Python 或 Docker 进程。

开发用 `scripts/start.ps1 -NoBrowser` 的常驻行为继续保留。重复点击桌面图标不创建相同数据目录的多个服务实例。

## 数据与升级

桌面版学习数据库、代码、笔记、备份、日志和运行产物存入 `%LOCALAPPDATA%\CodeTopLocal` 下的明确子目录，避免写入安装包临时解压目录或被升级覆盖的程序目录。

源码版原有 `data/` 不自动搬移、覆盖或合并。用户在旧版生成完整备份，再通过新版明确的恢复入口导入；恢复仍遵守服务锁、哈希、数据库一致性、升级前备份和失败回退。不得要求小白运行恢复命令或手工替换 SQLite 文件，桌面版需要可见的备份恢复入口。

AI Key 继续本机加密保存，不进入学习备份。首次本机执行确认记录也不随备份迁移。安装或升级程序不删除学习数据；本轮不新增批量清理脚本。

## 验收标准

自动测试先覆盖失效场景，再实现对应能力：

- 内置 Python 的选择不受系统 PATH、已有 Python、环境变量注入或用户当前工作目录影响。
- 首次确认前，两类执行接口都不能启动本机代码；取消不丢失草稿。
- 普通输出、中文、语法错误、运行异常、期望输出比较、20 组测试和请求重试沿用原行为。
- 交互提示及时可见；多次输入、空行、中文、EOF、停止以及 stdin 关闭行为正确。
- 死循环、超量输出、超量内存、子进程创建与退出、主进程退出后留存子进程等情况都能结束且不拖住应用。
- 关闭服务时没有本应用遗留的练习进程；不影响测试期间另行启动的无关进程。
- 原 Docker 显式模式的测试继续可运行，且本机模式健康检查完全不调用 Docker。
- 原完整备份、代码历史、题库导入、AI 配置与默认标签页生命周期回归通过。

打包验收以实际安装包为对象：在无 uv、Node、系统 Python、Docker 的 Windows 环境安装，双击快捷方式，看到 1,153 道题，执行 `print`、交互 `input` 和自定义样例；中文与空格安装路径、端口占用、重复启动、离线启动、升级数据保留均须检查。

同机清空 PATH 只能作为补充检查，不能冒充干净 Windows 环境验收。若本机无法提供虚拟机或 Windows Sandbox，需在交付说明中明确列出该项未完成的外部验收，不能宣称已经验证。

修改前端后运行 `scripts/build.ps1` 更新根目录发布，并通过原 `Start-CodeTop.cmd` 入口验收源码安装。新桌面发行另从实际安装后的快捷方式验收。
